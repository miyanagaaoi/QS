## 2. 如何运行

### 2.1 Docker Compose（推荐用于交付验收）

```bash
export XUNJIA_SECRET_KEY=$(openssl rand -hex 32)
export INITIAL_ADMIN_PASSWORD=Admin@2026
export SEED_DEMO=1
docker compose up -d --build
# 前端 http://<服务器IP>/    接口文档 http://<服务器IP>/docs
```

### 2.2 本机直接运行（当前演示环境即为此方式）

```bash
cd backend
./.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# 浏览器访问 http://127.0.0.1:8000/ 即可（后端已托管前端构建产物，含 SPA 路由回退）
```

前端开发模式另开终端：`cd frontend && npm run dev`（http://127.0.0.1:5173，`/api` 代理到 8000）。

| 账号管理 | 我方/供货商账号、批量导入（模板 + 预校验 + 错误报告导出）、启停用、重置密码、最后管理员保护 | FR-ACC |
| **首次登录改密改为按账号开关**（2026-10 变更） | 新建账号时可选"要求首次登录修改密码"，**默认关闭**；重置密码仍强制改密；列表按真实值显示「需改密」标记。安全性权衡见 PRD §14.5 | FR-ACC-15/16 |

| 响应式 | 三档断点（<768 / 768~1199 / ≥1200）、导航抽屉化、列表卡片化、加载更多 | FR-RWD-01~15 |

### 3.2 接口错误码一致性

所有错误响应统一为 `{code, message, data}`，**HTTP 状态码不再被当作业务码透传**：
未匹配路由/方法 → `40400`、参数错误 → `40001`、未登录 → `40100`、需改密 → `40101`、
无权限 → `40300`、已截止 → `40301`、业务冲突 → `40900`、服务端异常 → `50000`（与 PRD 7.6 一致）。

### 4.1 端到端脚本覆盖
认证与首次强制改密（含"开关关闭时不强制"的反向用例）、发布分派、发布前校验（无供货商 / 过去截止时间）、
已发布禁改明细、供货商保存为 partial、不含税单价计算（113.00→100.00）、改价版本递增、
越权 40300 与留痕、比价最低价/价差率、三类 xlsx 导出、日志只读、最后管理员保护、
**追加供货商（成功 / 重复拒绝 / 草稿拒绝）**、时间口径工程门禁。

脚本特性：
- 默认使用**专用账号 `e2e_admin`**（不存在时经引导管理员自动创建，且创建时**不要求首登改密**），
  因此可重复运行且不会改动 `admin` 的密码；
- 运行结束时自动停用本次创建的 `e2e_tmp_*` / `e2e_nopwd_*` 临时账号，不在库里留垃圾。

### 4.2 移动端元素级验收（375px）
**为什么不用 `scrollWidth` 单一指标**：本项目实测踩过坑 —— `AdminLayout` 手机端缺
`flex-direction: column` 时，顶部栏与内容区并排，内容区被压到 **156px** 并被
`body{overflow-x:hidden}` 静默裁切，而 `documentElement.scrollWidth` 仍是 375，
看起来"无横向滚动"。因此 `scripts/mobile-acceptance.sh` 采用**逐元素比较右边界**
（并排除自身可横向滚动的容器），同时输出内容区宽度与热区尺寸。

| 页面 | 375px 实测 |
|---|---|
| /purchase/rfq | 无越界、内容区 375px、7 张卡片、热区全部 ≥44px |
| /purchase/rfq/new | 无越界、明细卡片正常、Excel 导入入口已按 FR-RWD-12 隐藏 |
| /purchase/report | 无越界、比价表内部横向滚动 + 首列 `sticky` 冻结、热区 ≥44px |
| /system/account | 无越界、7 张卡片、热区 ≥44px |
| /system/dict | 无越界、22 张卡片、徽标无裁切、热区 ≥44px |
| /system/audit-log | 无越界、20 张卡片、热区 ≥44px |
| /supplier/quotes（供货商） | 卡片列表、无越界 |
| /supplier/quotes/1（供货商） | 8 张物料卡片、默认只展开单价、单价框实测 `type=text` + `inputmode=decimal` + **44px** + **18px**、折叠区默认收起、底部吸底栏"已填 x/y"、无越界 |

### 5.1 本批需求变更（2026-10）修复的问题

## 6. 尚未完成 / 需人工确认的事项（如实列出）

1. **真机验证（必须人工）**：PRD 第 11.7 节的 TC-43 ~ TC-67 共 25 条移动端专项，需在
   **真实 iOS + Android 设备**上执行（拍照/EXIF 旋转、iOS 聚焦放大、微信内置浏览器、
   断网重试、>10 行分段导航）。模拟器结果不作为通过依据。操作步骤见验收矩阵第 4.2 节。
2. **非 +8 时区设备**：若供货商手机时区不是 UTC+8，"截止时刻"文字会偏（倒计时不受影响）。
   当前按内网单时区决策实现，如需彻底消除需改为固定 `+08:00` 解析或改存 UTC。
3. **多 worker 部署**：导入 token 存进程内存，需要迁移到 Redis/DB（单进程部署无影响）。
4. **未实现（PRD 已排除或标注 P1）**：消息通知、审批流、多轮议价状态机、定标/下单、
   物料主数据、ERP/OA 对接、按物料历史报价走势（`GET /api/reports/material-trend`，
   PRD 标注 P1）、我方行图纸上传入口。
5. **前后端"预留但未实现"的接口**（已做一致性校验，避免维护者误判）：
   - `GET /api/reports/material-trend`（前端 `api/report.js` 已封装，后端未实现，P1）
   - `GET /api/admin/suppliers/export`（前端 `api/admin.js` 已封装，后端未实现；
     供货商账号清单导出由 `GET /api/admin/supplier-accounts/export` 提供）
   两处均已在代码注释中标注；本期不实现。
6. **文档与代码的静态检查**：未接入 ESLint/TypeScript；Alembic 目录未落地（当前用
   `create_all` 建表，代码注释已说明）。

## 7. 已知特性（不是缺陷，但需知晓）

| 项 | 说明 |
|---|---|
| **1366px 下列表需表内横向滚动** | 报价单列表有 9 列、表格总宽约 1290px，而 1366×768 下内容区约 1126px，需横向滚动才能看全列（属 FR-RWD-01 明确允许的"宽表格内部滚动"；页面级无横向滚动条）。1920 下无此情况。未做列收窄，因为会牺牲单号/时间的可读性。 |
| **时间口径为北京时间** | 全应用统一北京时间 naive（`models.app_now()`）。非 UTC+8 时区的设备上"截止时刻"文字会偏（倒计时不受影响，走 `remaining_seconds`）。 |
| **自动截止为"惰性 + 定时兜底"** | 接口读写时惰性判定，另有后台任务每 60s 扫描（`services/scheduler.py`）。 |
| **列表页页头未提供"导出"按钮** | 契约中没有"按筛选条件导出列表"的端点，为避免放假按钮而未实现；单据级导出与报表导出均已提供。 |
| **`AssigneeOut` 无"是否打开过填报页"字段** | 设计稿的「未打开填报页 / 已打开未保存」二级区分无法精确还原，界面统一表述为「尚未填报」，不做无依据推断。 |
| **`support.js` 是前端局部补齐** | `views/purchase/support.js` 补齐了基座未封装的 `/meta/*`、带 `rfq_id` 的导入预校验、比价导出等；`views/system/adminApi.js`（fe-admin）与 `views/supplier/quoteModel.js`（fe-supplier）同属各模块自建封装。基座 `src/api/admin.js` 无页面引用、`src/api/supplier.js` 被供货商两页引用 —— 均已在文件头注释标明实际使用方，改后端接口时需同步检查。 |
| **页签切换用 `router.replace`** | 账号管理 `?tab=internal\|supplier`、字典维护 `?tab=unit\|tax\|supplier` 均可刷新停留、分享链接定位；但**浏览器后退键不会在页签间往返**（避免污染历史）。如需后退键切页签，把 `replace` 改成 `push` 即可（各一处）。 |
| **`__verify__/` 目录** | 各模块自带的独立构建/契约自检夹具（`views/*/__verify__/`），非业务代码，不参与构建产物；保留以便回归复跑，可按需删除。 |

## 8. 交付前的工程约定

| 约定 | 说明 |
|---|---|
| 时间基准 | 业务代码禁止裸用 `datetime.now()` / `date.today()` / `astimezone(UTC)`，统一 `app_now()` / `to_app_tz()`；由端到端脚本的时间口径门禁自动校验（`scripts/e2e_acceptance.py` 第 7 节） |
| 断点 | 只在 `styles/breakpoints.scss` 定义，Vite 将其注入 JS 常量供 `useBreakpoint` 使用，CSS 与 JS 单一来源；业务组件禁止硬编码断点 |
| 接口契约 | 字段以 `backend/app/schemas.py` 为准；统一响应 `{code,message,data}`；金额与数量为字符串（避免 JS 浮点误差） |
| 权限 | 前端菜单隐藏仅是体验，**后端强制鉴权**；供货商数据隔离在服务端按 token 的 `supplier_id` 过滤，越权写 `security.forbidden` 日志 |
| 数据 | 金额数量一律 `Decimal`；改价历史与操作日志只追加、永不物理删除 |
| 验收账号 | 端到端脚本默认使用**专用账号** `e2e_admin`（首次运行自动创建），不使用 `admin`，避免改密类用例影响演示账号 |
